# Модель угроз: Списки покупок (shopping-list)

**Команда:** 2, участники: Дикмарова Мария (тимлид, настройка сервера, безопасность), Милана Мухина (база данных, логика), Арина Шитикова (интерфейс, тестирование)

## 1. Что мы строим
Схема (текстом):
Пользователь → браузер → наш сервер (Laravel) → база (SQLite) → папка с файлами (пока не используется).

Кто пользуется сервисом:
- Гость (неавторизованный пользователь): может только просматривать страницу входа и регистрации.
- Пользователь (авторизованный): может создавать свои списки покупок, добавлять, редактировать и удалять товары.
- Админ (в будущем): сможет управлять пользователями.

## 2. Что ценного (активы)
| Актив | Почему ценен |
|---|---|
| Данные пользователей (Email, хеш пароля) | Утечка позволит злоумышленнику подобрать пароль и войти под чужим именем. |
| Содержимое списков покупок | Это личные планы пользователей. Никто не хочет, чтобы посторонние видели, что он собирается купить. |
| Доступность сервиса | Если сервер упадет, пользователи не смогут открыть свои списки прямо в магазине. |

## 3. Кто захочет навредить (нарушители)

| Кто | Чего хочет | Что умеет |
|---|---|---|
| Любопытный пользователь | Подсмотреть чужие списки покупок | Менять цифры ID в адресной строке (например, /lists/1 на /lists/2) |
| Хакер-новичок | Украсть базу данных или сломать сайт | Вводить SQL-инъекции в поля форм, внедрять XSS-скрипты |
| Бот-переборщик | Подобрать пароль к чужому аккаунту | Отправлять тысячи автоматических запросов в секунду (Brute Force) |

## 4. Угрозы (хотя бы по одной на каждую букву STRIDE)

| № | Буква | Угроза (что именно произойдёт) | Мера защиты | Как проверим |
|---|---|---|---|---|
| 1 | S | Подмена личности. Злоумышленник подбирает пароль и входит под аккаунтом другого пользователя. | Laravel Breeze (пароли хешируются). В будущем — ограничение попыток входа (Rate Limiting). | Попробовать ввести неверный пароль 5-10 раз подряд. Сервер должен временно заблокировать вход. |
| 2 | T | Фальсификация данных. Пользователь меняет скрытое поле в форме (например, `user_id`), чтобы добавить товар в чужой список. | Сервер берет `user_id` из текущей авторизованной сессии, а не из данных формы. Валидация всех входящих данных. | Открыть DevTools (F12), изменить значение `user_id` в HTML-коде и отправить форму. Товар должен добавиться только в свой список. |
| 3 | R | Отказ от авторства. Пользователь удалил чужой список, а потом утверждает, что это сделал не он. | Ведение логов (логирование всех действий пользователей с указанием IP и времени). | Проверить файл логов (`storage/logs/laravel.log`) после удаления записи. |
| 4 | I | Утечка информации (IDOR). Посторонний открывает чужой список, перебирая номера в адресе: /lists/1, /lists/2... | Проверка прав на сервере (Laravel Policy). Если список не принадлежит пользователю, выдавать ошибку 404 Not Found. | Войти под Машей, создать список. Войти под Миланой и попробовать открыть URL со списком Маши. Должен быть ответ 404. |
| 5 | D | Отказ в обслуживании. Бот отправляет тысячи запросов на создание списков, сервер перегружается и падает. | Использование встроенного Middleware `throttle` в Laravel для ограничения количества запросов с одного IP. | Использовать утилиту для нагрузочного тестирования (например, `ab` или `JMeter`) и убедиться, что сервер отвечает 429 Too Many Requests. |
| 6 | E | Повышение привилегий. Обычный пользователь вручную вводит адрес /admin и получает доступ к панели администратора. | Проверка роли пользователя на сервере (Middleware для проверки прав доступа к админке). | Попробовать открыть /admin под обычным пользователем. Должен быть ответ 403 Forbidden. |
