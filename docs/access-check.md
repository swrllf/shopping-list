# Контроль доступа (access-check.md)

Команда: 3, проект: shopping-list, стек: Laravel

## 1. Матрица доступа

| Роль ↓ / Операция → | Просмотр списка | Просмотр записи | Создание | Изменение / Удаление |
| :--- | :--- | :--- | :--- | :--- |
| Гость | — | — | — | — |
| Пользователь | R (свои) | свои | да | свои |
| Админ | R (все) | R (все) | да | R, W (все) |

**Обоснование:** Гость не видит данные. Пользователь работает только со своими записями. Админ может модерировать все записи. Для удобства админа реализован режим «просмотра как пользователь» (через сессию), который не меняет реальную роль в базе, но скрывает админ-функции.

## 3. Результаты тестов (ручной протокол)

**Тест 1: Свой объект → 200**
- Войдя как User1, создали список «продукты».
- Открыли `/lists/1` под User1 — страница загрузилась (200 OK).

**Тест 2: Чужой объект → 404**
- В режиме инкогнито вошли как User2.
- Попытались открыть `/lists/1` (список User1).
- Результат: страница **404 Not Found**.

**Тест 3: Недостаточная роль → 403**
- В режиме инкогнито вошли как User2 (обычный пользователь).
- Попытались открыть `/admin/lists` (страница только для админа).
- Результат: страница **403 Forbidden**.

**Дополнительно (проверка режима «просмотра как пользователь»):**
- Под админом (Милана) нажали кнопку «Смотреть как пользователь».
- Ссылка «Все списки (Админ)» исчезла из меню.
- При попытке открыть `/admin/lists` в этом режиме — получен **403 Forbidden**.
- Нажали «Вернуться в админку» — доступ восстановился.
